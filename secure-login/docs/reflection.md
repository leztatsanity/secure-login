# Defensive Coding Reflection

Defensive input validation protects fintech applications by following the principle "never trust user input." By validating data at the system boundary, in both the frontend UI and the backend controller, malformed or malicious input is rejected before it can reach core business logic or the database. In our login system, blank fields and usernames containing unexpected characters (such as the quote marks in `' OR '1'='1`) are blocked immediately, and all database queries are parameterized so any remaining input is treated purely as data and never as executable SQL. This prevents injection attacks that could bypass authentication or expose account data. Combined with salted password hashing, account lockout after three failed attempts, and generic error messages that never reveal whether a username exists or leak stack traces, these layers reduce the risk of unauthorized access, brute-force attacks, and information disclosure, which is critical when real money and regulatory compliance are at stake.
